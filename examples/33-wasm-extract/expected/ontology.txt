# Ontologies in Relate WASM 1.2.0 (harness/ontology.mjs)
Every ontology is an Ontology Graph Spec v1 document (web/ogs.js): parsed by web/ontology.js, kept in an in-memory
store by applyOntology (the D8 layer and a CIP-176 graph type, D15) and read back. The 27 bundled ones are converted
(web/convert.js) from create-context-graph's domain files (data/ontologies/ccg/); the page and the harnesses load the
converted documents (data/ontologies/ogs/ccg/), and a create-context-graph file is converted on load. edgextract 0.1.0 (npm,
its own WASM) is the parity oracle for the ported splitter and names.
The example's own labels and relationship types all start with _ (_Entity, _Claim, _IN, ...); an ontology id may not.

## create-context-graph's domains (data/ontologies/ccg/, neo4j-labs/create-context-graph 707b168): 27, each inheriting _base.yaml
Each is loaded as the page loads it, its v1 document (data/ontologies/ogs/ccg/), converted from the file and _base.yaml.
Labels and relationship types are the files' own, verbatim. _base.yaml is merged as ontology.py _merge_base does: the
base's entity types and relationships first, unless the domain declares that label or relationship type itself. Entries
sharing a relationship type are one link with several legal (source, target) pairs, which is what the gate checks; a link
is typed in the graph type only when it has exactly one pair (R16). A kind's description (the page's, _Kind.description) is
derived: "<subtype> (<pole type>)", lower case with _ as spaces, or the pole type alone (ontology.js kindDescription).
The model is asked otherwise (pipeline.modelSchema, from each kind's and link's ask): a kind by its label as text
(ontology.js labelText), with "<subtype> in <domain name>" for a domain kind with a subtype and nothing for a base kind;
a base kind that no link names and whose pole a domain kind shares is not asked; a link as its phrase between its
endpoints' label texts, one per legal pair, joined by " or ".
