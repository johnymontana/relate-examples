The memory has a shape, and this is that shape written down: an ontology, in Neo4j's Ontology Graph Spec. It says what each label, property and relationship type means, which rules the engine enforces, and which it leaves to the agent. The document is JSON, checked against the engine and against every conversation on each run of the example.

    Does the store keep to it?

    The engine enforces types, required properties and the label at each end of a relationship. The rest of the model is the agent's to keep: which values a property takes, how many relationships a node has, what must hold between memories. Each rule is a statement that returns its violations, run on the store as it is now. To see one break, run “A write the engine allows and the model forbids” under the hood, then check again.

      Questions it answers

      The questions the model was written to answer. Click one to run its statement on the store as it is now. A parameter starts on a value the store holds; pick another to ask again.

        The agent is scripted. The database is not: every remember and recall on this page is a statement that Relate, compiled to WebAssembly, runs in this tab. The vectors are real too: each memory and each question is embedded with all-MiniLM-L6-v2, ahead of time for the scripts and in this tab for what you type. Nothing you type is sent anywhere; the model's files are the only thing fetched from another site.

        The shape of a memory, enforced by the engine

        A graph type declares what a memory is. The engine refuses a write that does not fit: a memory without its text or its kind, a vector of the wrong length, an edge between the wrong kinds of node. This is the graph type as the engine reads it back.
