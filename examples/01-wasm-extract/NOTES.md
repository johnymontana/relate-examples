# Example 01: the Relate 1.2.0 behaviours it depends on

Every engine behaviour this example depends on or pins, one row each. The ids (`R1` …) are what
the code, the harnesses and `expected/` cite. **Pinned by** names the file whose run fails when the
behaviour changes (a `PIN:` line on stderr, or a diff against `expected/`). Every row was re-checked
on Relate 1.2.0 (the npm package `@relate/relate-wasm@1.2.0`, the `relate` 1.2.0 CLI and the
`relate-db` 1.2.0 Python binding) on 2026-11-22. "Changed" marks what differs from the engine this
example was first written for.

## Design ids

The ids that carry a larger decision point to its ADR in [`docs/adr/`](../../docs/adr/README.md).

The design ids the code and outputs cite, defined here.

- **D1** One example, numbered 01. **D2** (ADR-0005) The engine: Relate 1.2.0, the release the npm package, the CLI and the Python binding share. **D4** (ADR-0010) The model: GLiNER2.5 through gliner-rs v0.3.1 compiled to WASM (small-v1 by default). **D5** edgextract's engine is not used; its approach, sentence splitter and name rules are, ported. **D6** (ADR-0010) One engine worker owns the store and the model; a console worker borrows the store. **D7** Inferences are cached per sentence in `(:_Inference)` nodes. **D8** The graph schema: the example's own labels and types start with `_`, which no ontology id may. **D9** (ADR-0006) No transactions (R2), so writes are idempotent and a section is committed by a marker. **D10** The gate is Cypher, every `$param` guarded on the parameter side. **D11** (ADR-0010) The Cypher console queries the live store through a lent read-only handle. **D12** Three test surfaces (Node, the browser, native) share one store module. **D13** (ADR-0010) The page's modules are unbundled; NVL is vendor-bundled. **D14** One ontology per store (`ex01-kg-<slug>`). **D15** The ontology document lives in `neo4j`, with a canary for `db.ontology.*` (R17). **D16** The extracted knowledge graph and its NVL view. **D17** Download (a snapshot tar) and restore. **D18** (ADR-0008) `lib/replay` carries graph types. **D19** (ADR-0002) The site: a static GitHub Pages project site for the repository's browser examples.
- **E1–E4** edgextract's rules as ported: E1 its ontology YAML (refused now, read only for the stores earlier builds made), E2 sentence splitting, E3 names, E4 its gate.
- **G1, G2, G5–G8, G10, G11** findings about the model: G1 the checkpoints, G2 Python gliner2, G5 gliner-rs's API, G6 its build, G7 parity with Python and determinism, G8 its cost, G10 long input collapsing (use per-sentence input), G11 its output shape (code-point offsets, one span under two labels).
- **O1, O3–O7** findings about ontologies on the engine: O1 `db.ontology.*` is not usable (R17), O3 `system_ontologies` (R17), O4 a graph type enforces endpoints and names (R16), O5 graph-type limits (R16), O6 graph types, constraints and indexes persist across `free()`, reopen and a native copy, O7 (ADR-0007) the move to the published spec: a store a draft-format build wrote has its document converted on open (`lib/ogs.mjs` `fromDraft`) and stored again in the published format; its sha256 changes, so it is gated and published once more, and the inference cache's keys (D7, which include the ontology) change with it: the next extraction of each section asks the model again rather than reusing the cached answers.
- **Y1, Y2** findings about the Ontology Graph Spec SDK (npm `@neo4j/ontology-graph-spec` 0.12.2), pinned in `ontology.txt`: Y1 its own YAML decoder (`GraphSpec.Yaml.decodeFromString`) misreads plain YAML: an unquoted `type: LIST<STRING>` throws `Neo4jType does not contain element with name ''`, an unquoted `schema: https://…` followed by `version: '1'` throws `Top-level decoder: deserializing nested class for '1'`, and none of the 27 bundled documents (js-yaml's output) decodes through it, so `lib/ogs.mjs` always parses with js-yaml and decodes the JSON (`GraphSpec.Json`), which reads all 27; Y2 its decoder ignores fields the spec does not have and accepts an integer `version`, so `web/ogs.js` runs the spec's JSON Schema first, which refuses both. The SDK also refuses a null custom value ("Custom values cannot be null"), which is why `fromDraft` writes `{}` for a draft envelope with no definition. The docs' `npm install @neo4j/ontology-graph-spec@1.0.0` names the spec version; no such package version exists.
- **V3–V8** findings about NVL: V3 loading, V4 rendering in headless Chromium, V5 interactions, V6 layouts (d3Force is deterministic, used by `?test=1`), V7 performance, V8 behaviour to code around.
- **X1–X5** the download and restore route: X1 read the store only after `free()`, and only the catalog-listed slots; X2 a restore writes the files into a fresh store in path order, the catalog last; X3 the native side (R22); X4 a native store as a restore input (`relate clone --to-snapshot-format json`, then `lib/opfsfmt.py to-tar`); X5 the strict format guard (`web/opfs.js`, `lib/opfsfmt.py`), pinned to Relate 1.2.0.

## Changes the port made (not engine behaviour)

- The download is a snapshot tar, `<store>.relate.tar`: `graph.json` and `manifest.json` only (R22). It used to be the whole directory database with both role markers, which spelled the engine's earlier product name.
- Restore and `lib/opfsfmt.py` skip dot entries by one rule. They no longer refuse a non-empty lease file (the rule cannot tell a lease from a marker or the schema mirror); `lib/opfsfmt.py` still refuses a directory whose dot file a running process holds locked (a live writer's lease). `to-dir` writes a snapshot directory; `to-tar` writes a snapshot tar; `--no-markers` is gone, `check --snapshot` is new.
- The page is published on GitHub Pages, which sends no headers of the site's own. What that costs, compared with a host that sets them:
  - The Content-Security-Policy is a `<meta>` element, and a meta policy ignores `frame-ancestors`, so it is left out: **the page can be framed** by any site.
  - **No `X-Content-Type-Options: nosniff`** and no immutable caching (Pages sends `max-age=600` on every file; the versioned `assets/<name>-<version>/` directories keep stale files out). The referrer policy is a `<meta name="referrer">`.
  - A module worker loaded from the site's origin runs with **no policy at all** (a policy reaches a worker only through its response headers).
  - **The origin is shared**: a project site lives on `https://johnymontana.github.io`, with every other Pages site of that account. Storage is per origin, so any of those sites can read, change or delete this page's OPFS stores (`relate/ex01-kg-*`), its model cache and its `ex01.*` `localStorage` keys. The `ex01` prefix only keeps the examples from colliding; it is not a boundary. Keep nothing private in a store, or serve the site from its own domain.
