model fastino/gliner2.5-small-v1 @ 7132dc4, gliner-rs@4fa741e; every candidate at p >= 0.10 is cached and stored (D7)
create-context-graph's ontologies are asked by label text ("maintenance record"), "<subtype> in <domain>" for a domain kind,
base kinds bare, a base kind no link names and a domain kind covers not asked, links between their endpoints ("person works
for organization"); sections of about 3000 bytes
gliner-rs ran on worker threads first, each question once (harness/infer.mjs); three answers asked again on this thread: identical
one store per ontology (D14): the 27 create-context-graph domains with a sample, and one for the harness's 12 fixtures
(harness/fixtures.mjs: edge cases, with the financial-services ontology); the fixtures, then the samples (samples.json order); each
document is extracted, gated and published
default gate (store.defaultGate, gliner2.5-small-v1; every ontology): entity keep 0.500 drop 0.300; relation keep 0.350 drop 0.200;
  type margin 0.050; relation margin 0.050; pole margin 0.250
rules: 0 no-name (a pronoun or no canonical name), 1 gazetteer, 2 one-kind / type-margin / pole-specific, 2b other-kind,
       3 unanchored / end-in-review, 4 illegal / self-loop, 5 band / hedged, 6 ambiguous / reversed, 7 verdict / claim-verdict.
       A line: band, rule, sentence (s<idx>), then
       "text" (KIND) p or "head" -[REL]-> "tail" p
Each document is listed as the gate leaves its store after the last document (the gate runs per store).
