## the ontologies' example queries (the `tools` custom extension) on the stores
The curated ontologies' tools were written for the graph this example extracts (D20, D22); the packages' queries for their
CSV sample data. Every canonicalQuery tool of each ontology runs on a copy of its store (store.dumpStore loaded by
lib/replay.mjs into a fresh in-memory database), with its arguments checked and typed as the page checks them
(web/console.js toolArgs: never a missing or null parameter, R3). Arguments: each parameter's example when it has one (every
curated tool's do, from its documents); else a STRING gets the name of the store's first kept entity of the tool's kind (else
its first kept entity, else "x"); a parameter whose description suggests a value ("(default: 10)") that value; a default its
default; numbers 10, booleans true, dates 2024-01-01, lists one name. A tool that requires GDS, APOC or a write (the packages'
projections, placeholder flags and constraints) is not run: the page's engine has neither library, and its console's lease
is read-only (R15).
Outcome: rows (1 or more), empty (0 rows), or error (the first line of the engine's message). Beside it, what the
page's note on the tool (web/console.js toolCompat, which never runs the query) predicted: rows, empty, error, an error if
reached (a clause before a call on a missing index can leave no rows) or checked at run (an index named by a parameter).
