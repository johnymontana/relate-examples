# Example 01 ships Neo4j's solution packages verbatim, each with an overlay of its own

Status: accepted · Decided: 2026-11-26 (01's D21) · Scope: example 01

`neo4j/studio-agent-use-cases` publishes solution packages: an Ontology Graph Spec document
(`ONTOLOGY.json`), its queries (`QUERIES.md`), a description and, for packages drawn from FIBO, a
source notice. They are real ontologies written by domain modellers, which is what example 01
needs beside its own curated ones (ADR-0019). The repository has no licence file.

**The packages are vendored verbatim**, at a pinned commit, by `harness/vendor-studio.mjs`: only
the four files above, each checked against a manifest of sha256 digests, and refused if it holds
the engine's earlier product name (checked by a digest of the name, so the name itself appears
nowhere here). They ship with the page under Neo4j's permission, which the repository owner
confirmed on 2026-11-26, as NVL's is recorded (ADR-0009); `THIRD_PARTY.md` and the example's
credits say so, and each FIBO notice ships beside its package.

**What this repository adds is an overlay beside each package** (`<id>.overlay.yaml`, read by
`web/studio.js`): colours, the descriptions the model reads, link phrases, identifier patterns,
the properties read from text (ADR-0021) and example arguments for the package's queries. The
page's document is the package with its overlay applied, generated by `harness/convert.mjs`, and
stripping the overlay gives the package back exactly, which `harness/ontology.mjs` pins. Packages
written against spec 1.0.0 are read as 1.1 (which only adds property aliases).

**Consequences.** Upstream files are never edited, so a new upstream commit is a re-vendor and a
diff of the manifest. An overlay names only elements the package has, so an upstream rename fails
the conversion instead of drifting.
